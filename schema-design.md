## MySQL Database Design

_Column names follow Spring Boot's default naming strategy (camelCase → snake_case). Lengths come from the `@Size(max = …)` constraints on each entity._

### Table: patient
- id: BIGINT, Primary Key, Auto Increment
- name: VARCHAR(100), Not Null (3–100 characters)
- email: VARCHAR(255), Not Null, valid email format
- password: VARCHAR(255), Not Null (min 6 characters, write-only in JSON)
- phone: VARCHAR(10), Not Null (exactly 10 digits)
- address: VARCHAR(255), Not Null
- date_of_birth: DATE, Not Null (must be in the past)
- emergency_contact: VARCHAR(10), Not Null (exactly 10 digits)
- insurance_provider: VARCHAR(30), Not Null (3–30 characters)

### Table: doctor
- id: BIGINT, Primary Key, Auto Increment
- name: VARCHAR(100), Not Null (3–100 characters)
- speciality: VARCHAR(50), Not Null (3–50 characters)
- email: VARCHAR(255), Not Null, valid email format
- password: VARCHAR(255), Not Null (min 6 characters, write-only in JSON)
- phone: VARCHAR(10), Not Null (exactly 10 digits)
- years_of_experience: INT, Not Null (≥ 0)
- clinic_adress: VARCHAR(255), Not Null
- rating: DOUBLE, Not Null (0–5)

### Table: doctor_available_times
- doctor_id: BIGINT, Not Null, Foreign Key → doctor(id)
- available_times: VARCHAR(255) (e.g. "09:00-10:00")

_Note: generated by `@ElementCollection` on `Doctor.availableTimes`. One row per time slot of each doctor; it is not an entity on its own._

### Table: appointment
- id: BIGINT, Primary Key, Auto Increment
- doctor_id: BIGINT, Not Null, Foreign Key → doctor(id)
- patient_id: BIGINT, Not Null, Foreign Key → patient(id)
- reason_for_visit: VARCHAR(50), Not Null (6–50 characters)
- appointment_time: DATETIME (must be in the future)
- status: INT, Not Null (0 = Scheduled, 1 = Completed, 2 = Cancelled)
- notes: VARCHAR(100), Nullable

_Derived (not persisted, `@Transient`):_
- `endTime`: `appointmentTime` + 1 hour
- `appointmentDate`: date part of `appointmentTime`
- `appointmentTimeOnly`: time part of `appointmentTime`

### Table: admin
- id: BIGINT, Primary Key, Auto Increment
- username: VARCHAR(20), Not Null (3–20 characters)
- password: VARCHAR(255), Not Null (min 6 characters, write-only in JSON)

### Relationships
- A **doctor** has many **appointments** (`appointment.doctor_id`, `@ManyToOne`).
- A **patient** has many **appointments** (`appointment.patient_id`, `@ManyToOne`).
- A **doctor** has many **available time slots** (`doctor_available_times`).
- An **appointment** can have prescriptions in MongoDB (`prescriptions.appointmentId`).

## MongoDB Collection Design

### Collection: prescriptions
```json
{
  "_id": "ObjectId('64abc123456')",
  "patientName": "John Smith",
  "appointmentId": 51,
  "medication": "Paracetamol",
  "dosage": "500mg every 6 hours",
  "doctorNotes": "Take after meals.",
  "refillCount": 2,
  "pharmacy": {
    "name": "Walgreens SF",
    "location": "Market Street"
  }
}
```
- `_id`: String / ObjectId, generated by MongoDB
- `patientName`: required, 3–100 characters
- `appointmentId`: required, references `appointment.id` in MySQL
- `medication`: required, 3–100 characters
- `dosage`: required
- `doctorNotes`: optional, max 200 characters
- `refillCount`: required, integer ≥ 0
- `pharmacy`: required, embedded document (validated with `@Valid`)
  - `name`: required, 3–100 characters
  - `location`: required, max 255 characters
